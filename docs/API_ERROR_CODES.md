# API 错误码定义

## 📋 文档说明

本文档定义了Easy Lowcode平台所有API的标准错误码、HTTP状态码和处理指南。

- **更新日期**: 2026-07-11
- **适用版本**: 1.0.0+
- **维护人员**: 开发团队

---

## 🎯 错误码分类体系

```
┌─ 通用状态码 (1xx-5xx HTTP标准码)
├─ 认证授权 (10000-10999)
├─ 数据源模块 (20000-20999)
├─ 资源模块 (30000-30999)
├─ 大屏模块 (40000-40999)
├─ AI模块 (50000-50999)
└─ ETL模块 (60000-60999)
```

## 1️⃣ HTTP标准状态码

| HTTP Code | 含义 | 说明 | 前端处理 |
|-----------|------|------|---------|
| **200** | OK | 请求成功 | 正常处理响应数据 |
| **201** | Created | 创建成功 | 刷新列表/返回新ID |
| **204** | No Content | 删除成功 | 刷新列表 |
| **400** | Bad Request | 请求参数错误 | 显示错误消息，用户修正 |
| **401** | Unauthorized | 未授权(Token无效/过期) | 清除Token，跳转登录页 |
| **403** | Forbidden | 禁止访问(权限不足) | 显示"无权限"提示 |
| **404** | Not Found | 资源不存在 | 显示"不存在"提示 |
| **409** | Conflict | 资源冲突(如重名) | 显示冲突信息，让用户重试 |
| **422** | Unprocessable Entity | 业务规则校验失败 | 显示业务错误提示 |
| **429** | Too Many Requests | 请求过于频繁(速率限制) | 提示"操作过于频繁"，稍后重试 |
| **500** | Internal Server Error | 服务器内部错误 | 显示"系统异常"，建议联系技术支持 |
| **502** | Bad Gateway | 网关错误(依赖服务不可用) | 同500 |
| **503** | Service Unavailable | 服务不可用(维护中) | 显示"系统维护中"，稍后重试 |
| **504** | Gateway Timeout | 网关超时 | 同500 |

## 2️⃣ 通用错误码 (200-3xx)

| Code | HTTP状态 | Message | 说明 | 前端处理 |
|------|---------|---------|------|---------|
| **0** | 200 | 操作成功 | 正常成功响应 | 正常处理 |
| **1** | 400 | 请求参数错误 | 参数格式/类型不对 | 显示错误信息提示用户修改 |
| **2** | 400 | 参数验证失败 | 某个字段验证不通过 | 高亮显示有问题的表单字段 |
| **3** | 401 | Token不存在或已过期 | 需要重新登录 | 清除Token，跳转登录页 |
| **4** | 401 | Token格式不正确 | 格式不符合JWT标准 | 清除Token，重新登录 |
| **5** | 403 | 您无权访问该资源 | 缺少权限字符串 | 显示无权限提示 |
| **6** | 404 | 资源不存在 | 记录ID未找到 | 刷新列表，重新查找 |
| **7** | 409 | 资源已存在 | 名称/编码重复 | 显示冲突信息，建议修改名称 |
| **8** | 500 | 服务器内部错误 | 未预期的异常 | 显示系统异常提示，收集错误ID用于反馈 |
| **9** | 503 | 服务不可用 | 数据库/Redis离线 | 显示系统维护提示，稍后重试 |
| **10** | 429 | 请求过于频繁，请稍后再试 | 触发速率限制 | 禁用按钮5秒，显示倒计时 |

## 🔧 前端标准处理方案

### 全局错误处理流程

```typescript
// src/utils/request.ts - Axios响应拦截器

interceptors.response.use(
  (response) => {
    const { code, message, data } = response.data;
    
    // HTTP 200 但业务code不同
    switch(code) {
      case 200:
        return data; // 自动解包
      case 401:
        clearToken();
        router.push('/login'); // 重新登录
        return Promise.reject(new Error(message));
      case 403:
        ElMessage.error(`无权限: ${message}`);
        return Promise.reject(new Error(message));
      case 400:
      case 422:
        ElMessage.error(message);
        return Promise.reject(new Error(message));
      default:
        ElMessage.error(`系统错误[${code}]: ${message}`);
        return Promise.reject(new Error(message));
    }
  },
  (error) => {
    // HTTP 5xx错误
    if (error.response?.status >= 500) {
      ElMessage.error('系统异常，请稍后重试');
    }
    // HTTP 4xx客户端错误
    else if (error.response?.status >= 400) {
      ElMessage.error(error.response?.data?.message || '请求失败');
    }
    // 网络错误
    else {
      ElMessage.error('网络连接失败');
    }
    return Promise.reject(error);
  }
);
```

## 📞 错误码使用指南

### 前端开发者

1. **显示错误信息**: 所有code >= 400的错误都应显示给用户
   ```typescript
   if (response.code >= 400) {
     ElMessage.error(response.message);
   }
   ```

2. **区分可重试和不可重试**:
   ```
   可重试: 500, 502, 503, 504 (服务器故障)
   可重试: 429 (超限，等等再试)
   不可重试: 400, 401, 403, 404, 422 (客户端错误)
   ```

3. **自动重试策略** (HTTP 5xx):
   ```typescript
   // 最多重试3次，指数退避
   let retries = 0;
   while (retries < 3) {
     try {
       return await api.get(...);
     } catch(e) {
       if (e.response?.status < 500) throw e; // 4xx不重试
       retries++;
       await sleep(Math.pow(2, retries) * 1000);
     }
   }
   ```

### 后端开发者

1. **规范地抛出异常**:
   ```java
   // ❌ 不要硬编码数字
   throw new Exception("User not found");
   
   // ✅ 使用业务异常
   throw new BusinessException(10001, "用户名不存在");
   ```

2. **使用GlobalExceptionHandler统一处理**:
   ```java
   @RestControllerAdvice
   public class GlobalExceptionHandler {
     @ExceptionHandler(BusinessException.class)
     public Result<Void> handleBusinessException(BusinessException e) {
       return Result.error(e.getCode(), e.getMessage());
     }
   }
   ```

3. **关键操作记录日志**:
   ```java
   if (e.getCode() == 30011) { // SQL注入
     log.warn("SQL injection detected: {}", params);
   }
   if (e.getCode() == 10001) { // 用户不存在
     log.info("Login attempt with non-existent user: {}", username);
   }
   ```

## ❓ 常见问题

**Q: 同一个错误既有HTTP状态码也有业务code，应该选哪个？**

A: HTTP状态码用于HTTP层面的通信（框架自动处理），业务code用于应用层面的错误分类（需要前端处理）。两者都应返回。

**Q: 前端如何区分临时错误（应重试）和永久错误（不应重试）？**

A: 
- 临时: HTTP 5xx, 429, 50013 (AI不可用), 60011 (任务已运行) → 应重试
- 永久: HTTP 4xx (除429外), 其他业务错误 → 不应重试

**Q: 新增模块如何定义错误码？**

A: 按格式 `{模块编号}{细分类编号}{具体错误}`，如 AI模块(50000) + 对话(00) + 重复(01) = 50001。
